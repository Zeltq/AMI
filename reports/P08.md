## Что сделано

- `gpu/src/ggd_ppo.rs`: GGD recurrent PPO, фиксированный teacher-v9, сбалансированные стороны, окружение 003, общий `advance_teacher` (4 тика, offset=6), reset 128/смерть, FP16 observations, masks из evaluate.
- Награда: LH +1, deny +.5, LH/deny соперника −.5/−.25, смерти −10/+10, T1 −10/+10, результат дуэли на 600 с ±5 (ничья 0). Компоненты логируются отдельно.
- Прогрев обучает только `value_first`/`value_second` через detached recurrent state; выход при EV>.3 либо лимите блоков.
- KL(current‖M2): неотрицательная importance-weighted оценка `ρ*(exp(-d)-1+d)`, d=logπ−logM2, ρ=π/πrollout; ρ участвует в градиенте. Это выборочная оценка, не полный перебор условных голов.
- Профиль читается из manifest чекпоинта; размер rollout определяется наблюдением. ggd-v2/v3 поддержаны; для v4 требуется подключение observer P07 после его слияния, неизвестный профиль отклоняется явно.
- `experience.rs`: параметризованный GAE при сохранении прежних default; `main.rs`: только модуль и команда `train-ggd`.
- `p08_run.py`: OS-lock, фоновые subprocess, PID/статус/команды, контроль общего бюджета. `p08_results.py`: сравнение всех весов, метрики, CSV/SVG.
- Начальные параметры (до smoke): Adam ε=1e-8, lr=1e-5, critic lr=1e-4, 16 матчей, minibatch=4×128, 2 PPO epochs, clip=.2, grad norm=.5, value coefficient=.5, normalized entropy=.005, stop KL=.02, anchor .1→.01 линейно по времени. Warmup limit=32 блока; seed=20261103.
- Checkpoint каждые10мин, оценки каждые60мин и в конце, sampling/argmax по64 матчей, seed=20261103.
