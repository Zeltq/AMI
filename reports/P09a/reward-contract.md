# Телеметрия демонстраций P09a

Профиль политики остаётся `ggd-v4`, oracle выключен. Дополнительные данные
привилегированные и не входят в `decode`, encoder, previous или loss imitation.

`dataset.json.reward_metadata` связывает датасет с `reward-metadata.json` по SHA-256.
Последний содержит схему и список `.reward.npz`, SHA-256 и имя соответствующего
`.ggd.gz`. Порядок actor и решений совпадает с блоком демонстраций.

В каждом NPZ:

- `state`: FP32 `[actors, 128, 2, 26]`; фазы `before`, `after` относительно
  исполнения очередных четырёх физических тиков.
- `fields`: имена 26 полей; `actors`: глобальные ID героев, `game = actor // 2`.
- `valid`: маска решений из signals[11]; padding и решения после конца не обучаются.
- `match_outcome`: `-1/0/+1` — поражение/ничья/победа с точки зрения actor;
  финальный исход записан на каждом решении.
- `match_reason`: `1/2/3` — смерть/T1/LH на 600 с; итоговая причина на каждом решении.

26 полей состояния: игровые секунды; по десять полей своего и вражеского героя
(LH, deny, HP/maxHP, mana/maxMana, уровень, XP внутри уровня, суммарный XP,
души, активные стаки койла, смерти); HP/maxHP своей и вражеской T1;
текущие terminal, result, reason. До конца текущие result/reason не являются
будущей меткой; для будущей метки используются `match_outcome/match_reason`.

XP total = XP внутри уровня + сумма порогов всех завершённых уровней.
Активные стаки = 0 после окончания STACK_END, как при расчёте урона.
В существующем supplement ggd-v4 raw stacks могут сохраняться после истечения
дебаффа; профиль по условию задачи не исправляется.

`state[..., 1, 23]` — terminal после перехода. Герой, умерший до 0:00, может
не иметь валидного решения при завершении матча на 0:00; финальные метки
на его прошлых решениях всё равно присутствуют. Для DAgger следует сохранять
различие смерти, life-reset и конца матча.

Исход сохраняется событием до сброса арены функцией observe(). При одновременной
смерти и падении T1 для строки причины используется смерть. Победитель берётся
из штатного результата физики; это правило именования причины не меняет исход.

Проверка: состояния обоих actor совпадают при смене own/enemy; видимые поля
совпадают с независимой FP16 упаковкой наблюдения (допуск 0.001 в нормированной
шкале); конечные LH/deny/уровень/XP/души/смерти совпадают с замороженной
метрикой матча; исход и причина совпадают с событием завершения. Дополнительно
GPU-тест проверяет источники смерти, расстояния, XP total и истечение стаков.
