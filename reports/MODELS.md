## Сравнение против teacher-v9 при sampling

Общая серия [P02](P02.md): GPU-симулятор, `--mode teacher --sampling`,
64 матча на модель (32 Radiant и 32 Dire), seed `20261103`, горизонт 600 игровых
секунд либо штатный конец матча. Учитывается только собственная модель — одна
сторона на матч. Ранние смерти — матчи с первой смертью при игровом времени
строго меньше 120 с, включая pregame. LH и deny — суммы за все 64 матча.

Исходные измерения: [M0](P02/M0-sampling.json),
[M2](P02/round-2-sampling.json), [M4](P02/round-4-sampling.json),
[D0-контроль](P02/control-sampling.json). Метрики сверены с локальными отчётами
этапов из `state.json` и с [итогом P02](P02/final-summary.json).

M2 выбрана сначала по меньшему числу ранних смертей, затем по большему собственному
LH+deny. После M0 она получила 3894 обновления в двух раундах DAgger; M4 — 7673
за четыре раунда. D0-контроль продолжает M0 на исходном датасете D0 без DAgger
с тем же бюджетом 7673 обновления, что у M4. Лучший результат M2 пока не достигает
критерия P02: ≤2 ранних смертей и ≥2226.5 LH+deny за 64 матча. Учительский ориентир
равен 4453 LH+deny на 64 стороны (8906 на 128 сторон в 64 матчах teacher-vs-teacher).
Выбор подтверждён одной фиксированной серией seed; независимая серия не проведена.

## Другие выборки M0 и перенос в Dota

- [P01](P01.md): исходная серия M0 при sampling — 316 LH+deny за 32 матча.
  В таблице выше приведена отдельная общая серия P02 на 64 матча.
- [P05](P05.md): PyTorch-пакет M0 получен из указанного Burn-экспорта командой
  `gpu/scripts/export_policy.py`. В Dota на CPU при sampling сыграно 20 матчей
  (10 за сторону): LH 37, deny 13, всего 50 LH+deny; смерти — 15/20,
  pregame-смерти — 0/20. Эта серия сохраняет исходный знаменатель 20.
- Профиль Dota — `ggd-v2`, вход FP16→FP32, previous из выданной команды,
  сброс LSTM через 128 решений и после смерти. В P05 перенос подтверждён частично;
  причинность расхождений наблюдений и механики не установлена. Для M2, M4 и
  D0-контроля измерений в Dota в P02/P05 нет.

## Проверка локальных артефактов

На дату реестра существуют все четыре checkpoint, четыре Burn-manifest,
236/236 файлов тензоров и PyTorch-пакет M0 для Dota. Для каждого Burn-экспорта
проверены размеры и SHA-256 всех 59 файлов по manifest; все 59 тензоров каждого
экспорта побитово совпадают с соответствующим checkpoint после преобразования
раскладки. Ещё 59/59 тензоров Dota-пакета M0 совпадают с исходным checkpoint.

У M0 обнаружено ограничение provenance: `source_sha256` в старом Burn-manifest
равен `0d3b170bf2febf5d63fdf212b83f86bc46f7ad7698ce4c4a0a8e59fa0d37b15c`,
а SHA-256 текущего файла `epoch-003.pt` —
`6a9975661fda4cef8e89570ae37c3c9be9b416d507a60173d1111268409e45fb`
(совпадает с [provenance P02](P02/provenance.json)). Причина расхождения хеша
всего файла не установлена; равенство весов проверено отдельно, как указано выше.
У M2, M4 и D0-контроля `source_sha256` совпадает с текущими checkpoint.
