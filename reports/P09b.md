## Что сделано

- Выбор RL: **ZOg-d1**. Принимаю уступку d2 в4/128 побед и26/128 матчей со смертью: d1 имеет farm1401/10058 против1177/11240, койлы422/1149 против267/1214 попаданий/кастов, ранние12/128 против30/128; Dire15/64 побед против1/64. Приоритет — фарм, койлы и игра за обе стороны. Полное обоснование и SHA: [selection.json](P09b/selection.json); NLL не использована для выбора.

- `p09b_rl.py`: последовательные этапы references/critic/smoke/warmup/main; основное обучение возобновляется с последнего полного checkpoint, после 480 минут новый PPO не запускается. `p09b_run.py` блокирует живые дочерние процессы и восстанавливает консервативный расход GPU при сбое контроллера.
- Checkpoint и кэш критика сохраняются атомарно; тест прерванной записи сохраняет прошлый checkpoint. Кэш фиксированного hidden — FP16; config фиксирует SHA датасетов. GPU-этапы этих проверок ещё не выполнялись.
- Для ревью сохранены статистики каждого матча в `P09b/*-vs-*-SEED.json` без покадровых реплеев, вместе с аргументами оценок и SHA манифестов весов.

- `potential_reward.rs`, `p09b_reward.py`: новый режим potential-v1, gamma 0.99, веса 0.5/0.2/3/0.5, исход ±10; старая награда P08 сохранена. Численная таблица: [reward-table.json](P09b/reward-table.json). Койл по герою: +0.190/+0.359/+0.480/+0.557 на уровнях 1/3/5/7, поэтому вес маны 0.5 сохранён.
- Исправление minibatch: potential-v1 выбирает 48 последовательностей ученика, исключая строки соперника; прежний режим P08 сохраняет свой порядок. Целевой CPU Rust-тест 1/1.
- `ggd_ppo.rs`: ggd-v4/v10, отдельный lr value-головы, восстановление model/Adam/времени KL, оценки обоих соперников внутри процесса. `imitation.rs`: --opponent-weights для разных моделей; `teacher_eval.rs`: reward обеих сторон.
- CPU-проверка value на реальных 1024/1024 решениях pregame и 1024/1024 после 0:00: 4/4 value-тензора изменены, хеш остальных весов неизменен; max ошибка FP16-кэша value 0.000115. Возвраты P09a и d1 готовы: [demo](P09b/return-targets-demo.json), [d1](P09b/return-targets-d1.json).
- `p09b_critic.py`: замороженные recurrent features, только value head, Adam 3e-4, batch 8192, до 8 эпох; выбор по validation MSE, EV pregame/post0 отдельно. GPU-проверка и запуск ещё впереди.
- CPU-проверки P09b 7/7; полный Python после изменений 214/214; cargo check exit 0. GPU-тесты reward3/3 и полный Rust110/110 пройдены; 10-минутный PPO smoke и возобновление ещё впереди.

- Создан отдельный worktree C:/AMI-wt/P09b, ветка agent/P09b-zog-rl от P09a. В C:/AMI ветка и коммиты не изменяются.
- DAgger: beta 0.5/0.25, по 256 матчей, ggd-v4/005, teacher-v10 для меток и соперника. Один проход новых train-последовательностей, не менее половины новых кадров в батче; AdamW из предыдущего checkpoint, lr 1e-4, batch 8×128, clip 1, wd 1e-5. ATTACK крипов/башен 4, героя 1; near/mid/far 4/2.93/4, как в P09a.
- План RL: 192 арены, batch 48×128, epochs 2, actor lr 3e-5, critic lr 3e-4, clip 0.2, entropy 0.005, stop_kl 0.02, gamma 0.99, GAE lambda 0.95. KL 0.05→0.01 за 480 минут без сброса; оценки отдельно от времени обучения.
- Решение: оценки sampling на seed 20261103/20261104, по 64 матча; 64 за сторону суммарно. P09a переиспользуется только при полноте полей; недостающая награда требует повторной оценки с новым логированием.
- Решение: полезный койл проверяется по изолированному вкладу события; общий шаг дополнительно содержит (gamma−1)×старый потенциал. Проверка телескопирования использует дисконтированную сумму и конечный потенциал 0.
